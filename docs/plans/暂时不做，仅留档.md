# pi-vcc-codemode 0.1.3 改进计划

## 一、版本目标

建立一个最小、可靠的**任务连续性层**。无论压缩 1、5 还是 10 次，模型都能看到：

- 当前目标；
- 仍然有效的约束；
- 已完成的重要进展；
- 下一步；
- 未解决问题；
- 可供 `vcc_recall` 查询的 `#N` 来源。

成功标准不是“保留更多历史行”，而是**减少目标偏离、重复调查和重复操作**。

## 二、本版范围

### 必须完成

1. `pi-vcc.current-task` 状态存储与分支重放。
2. `[Current Task]` 有界摘要区。
3. 状态替换、删除后旧内容不复活。
4. codemode 摘要覆盖范围说明。
5. 1/5/10 次压缩、分支、恢复和 `context_edit` 测试。
6. 中英文状态内容测试。

### 明确不做

- nested calls 完整分页；
- 旧 compaction summary 的独立召回接口；
- 自动判断任务完成、目标替代关系；
- 通用中文语义状态机；
- 将默认摘要预算提高到 5K/10K；
- 复杂任务 DAG。

## 三、Current Task 数据结构

```ts
interface CurrentTaskV1 {
  version: 1;
  goal: string;
  constraints?: string[];
  progress?: string[];
  next?: string;
  blockers?: string[];
  sourceRefs?: `#${number}`[];
}
```

约束：

- `goal` 必填，其他字段可选；
- 每次写入完整替换对象，不做字段级合并；
- 任务结束时执行 `store("pi-vcc.current-task", undefined)`；
- JSON 最大 8 KiB；
- 列表分别限制为 4–8 项，单项不超过 200 字符；
- 摘要投影最多 600 字符；
- 所有内容标注为 `declared`，不冒充验证事实；
- `sourceRefs` 必须能映射到真实的全局消息编号，否则丢弃。

Pi 已按当前分支从根部重放 store，顺序是先删除、再写入：[execute.js:233](node_modules/@earendil-works/pi-coding-agent/dist/extensions/codemode/execute.js#L233)。插件应复制这一小段稳定语义，不依赖未公开的内部模块路径。

## 四、摘要形态

```text
[Current Task]
- Goal (declared): 修复压缩后目标丢失
- Constraints (declared): 不增加压缩阶段的 LLM 调用
- Progress (declared): 已确认 store 可按分支恢复
- Next (declared): 接入摘要编译链
- Blockers (declared): 尚未验证十次压缩
- Sources: #123, #140

[Recall Coverage]
- This is a selective view. Original #N entries remain recallable;
  earlier compaction summaries are not directly recallable.
```

`[Current Task]` 和 `[Recall Coverage]` 都采用 **fresh-only** 合并：每次根据当前真实状态重建，不继承旧区段。现有合并入口在 [src/core/summarize.ts:206](src/core/summarize.ts#L206)。

状态矩阵：

| 状态            | 摘要行为                |
| ------------- | ------------------- |
| 从未写入          | 不显示 Current Task    |
| 合法状态          | 显示有界投影              |
| 新状态替换         | 只显示新状态              |
| 已删除           | 移除旧区段               |
| 非法或版本未知       | 显示短诊断，旧状态不复活        |
| codemode 未激活  | 暂不投影状态，保留 store     |
| 有 codemode 历史 | 仍显示 Recall Coverage |

## 六、预算策略

0.1.3 不改以下默认值：

- ranked floor/ceiling：1100/2000 tokens；
- `maxBlocks`：80；
- codemode 段补回：1000 字符；
- previous brief：120 行。

Current Task 使用独立 600 字符硬上限。真实任务中新增上下文成本的中位数应不超过 **250 tokens**；超过则先压缩状态格式，而不是扩大总预算。

通用中文提取和 CJK 截断暂缓，因为它们会影响所有会话；本版通过显式状态原生支持中文，避免修改 [src/extract/goals.ts:5](src/extract/goals.ts#L5)等上游共用路径。

## 七、发布门

至少进行两类固定任务，每类三组 0.1.2/0.1.3 配对续跑：

1. 中途改变目标和约束；
2. 脚本失败后保留进展与 blocker。

必须满足：

- 6 次中至少 5 次写入合法状态；
- 正确下一步不低于 0.1.2；
- 约束遗漏和重复工作不高于 0.1.2；
- 旧目标复活为 0；
- 所有确定性测试通过；
- 总 token 成本可解释。

未达到行为门时，不靠增加预算掩盖问题，应先调整 guideline 或缩减 schema。

预计工作量约 **5–7 个工程日**。该方案回退安全：0.1.2 会忽略已有 `codemode-store` 条目，不需要迁移或删除用户数据；目前未修改任何文件。
