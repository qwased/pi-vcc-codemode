## 1. 最终结论

**采用“模型注释辅助选择、简报保留历史导航、原始记录提供证据、召回修复信息损失”的路线。**

不因模型声明可能出错而否定其排序价值，也不因愿意信任模型而把声明升级成执行事实。系统应控制错误的影响范围：注释只能有限影响保留顺序，不能证明成功、取消失败证据，或变成永久有效的当前状态。

本版不沿用第五稿直接施工，也不按“声明、状态、血缘、配置一次建齐”的方向扩建。真正需要闭环的是：

1. 用户要求与助手发现有各自的预算，按原始时间顺序保留可读摘录。
2. 脚本活动在预算内分层选择；潜在写入优先，但不是无条件压过一切只读证据。
3. 注释语法不作为简报正文反复出现；保留有导航价值的简短意图。
4. 历史简报的保留策略跨压缩轮次生效，而非仅对本轮新消息打分。
5. 可明确请求搜索完整的已存文本，并按稳定出处分段读完，而非“搜索到了但永远只能看到头部”。

本版承诺信息呈现、预算和访问接口可以验证，不承诺仅凭这些改动保证模型永不偏离任务。

## 2. 用户意见与逐项裁定

| 编号 | 用户意见 | 最终裁定 | 必须保留的限定 |
|---|---|---|---|
| D1 | 注释可以仅辅助算法打分，不必代表真实情况。 | **采纳。** 注释是价值判断的弱信号，不是事实认证。 | 加分有上限；不写不扣分；重复标签不累加；声明不得覆盖调用结果。 |
| D2 | `//GOAL`、`//blocked` 不进入简报，开头说明阅读方式即可。 | **部分采纳并澄清。** 隐藏注释语法和 blocked 正文；保留简短 goal 正文作为“当时意图”。 | 完全删除 goal 正文，会使同样的 `edit(a.ts)` 丧失“为何修改”的区别，与保留写入意图的目标冲突。阅读提示统一说明，条目仍保留角色及出处。 |
| D3 | `//NEXT` 极不确定，应取消。 | **采纳。** 本版不解析、不加分、不渲染 next。 | 不通过新的名称变相引入下一步状态、完成状态或任务状态机。 |
| D4 | 应相信模型的能力；召回不对可以继续召回或修正。 | **采纳为容错原则。** 允许排序判断有误，并提供便宜、可操作的纠错路径。 | 模型未必察觉错误；破坏性操作仍应重新核实。不能用“将来可以召回”替代可发现的省略位置与可解析出处。 |
| D5 | 短用户消息可能是转向，长用户消息可能是任务书。 | **采纳。** 不以长度推断重要性或当前目标。 | “好的”“第二种”依赖前一条内容；对长任务书据以执行前，应确认被截断中段是否需要找回。 |
| D6 | 助手消息可能含关键发现，应与用户消息分别保留。 | **采纳。** 用户、助手正文、工具活动独立分配预算，未用额度可借用。 | 助手正文不是执行事实；不等于保留隐藏推理、全部工具结果或重复灌水。 |
| D7 | 超预算应截断长文本并说明剩余字符，不应只留下一个标记。 | **采纳为正常路径。** 先保留可读头尾，再说明实际省略量与出处。 | 正文最低摘录、角色、出处和提示也要计费；短文本不额外改写。 |
| D8 | 不设条目上限，只按字符预算限制每条长度。 | **取消固定条数上限，但不承诺无限非空条目。** | 固定总预算、无限条目、每条非空不可同时满足；最低可读摘录仍装不下时，允许折叠较旧连续片段并提供召回边界。只控单条、不控总量会无限增长。 |
| D9 | 用户、助手消息应与 codemode 命令保持原有上下位置。 | **采纳。** 分类只用于分配预算，输出恢复原时间线和同一消息内的块顺序。 | 不先输出全部用户文字再输出全部助手文字；不得因选择器重新分组而制造错误因果顺序。 |
| D10 | 写入意图优先，其次近期只读，再次远端只读；省略时留指针。 | **采纳为默认倾向，不作为绝对等级。** | 失败证据、变更前快照、偶发输出等可能比重复写入更重要；未知操作不冒充只读。 |
| D11 | 较早只读价值通常低，召回和重新读取成本相近。 | **部分采纳。** 稳定文件的重复读取可以优先淘汰。 | 变更前文件、轮转日志、远端响应和偶发失败无法保证重现；“工具次数相同”不等于时间、token、外部费用和历史信息相同。 |
| D12 | 无论压缩几次，recall 都应能搜索本会话全文。 | **采纳为访问契约。** 提供完整已存文本的显式字面扫描与分段读取，不以压缩轮次限缩语料。 | 默认分支与全分支必须明确；默认相关性搜索仍可近似，但不能冒称无损全文搜索。宿主未保存的数据、隐藏推理、图片像素及排除的派生内容不在该契约内。 |

D2、D8、D10、D11 的限定是本次裁定的重要部分，不能在执行计划中删掉，只保留“全部采纳”。

## 3. 论文支持什么，不支持什么

论文 §2.1–2.4 的主要启发是三种视图共享稳定坐标：概览保留角色、时间结构及指针，针对性检索定位内容，再按指针查看完整记录。相关性判断本身允许使用规则、BM25、向量或 LLM，因此不能从论文推出“筛选信号必须都是事实”。

但论文也明确区分工具调用的意图与工具结果的观察。它没有支持把 `goal`、`blocked` 或某个工具名称直接转换为“已完成”“当前仍阻塞”“已经创建文件”。

论文 §3 的实验改变的是 AppWorld 反思器读取轨迹的格式，再评估所产生的记忆；并未验证本仓库的反复在线压缩、注释权重、字符预算或跨轮重建策略。论文可作为方向依据，不能替代本版测试与对照实验。

## 4. 注释的最终语义

### 4.1 goal

- 继续使用固定标记 `// goal: <text>`，识别大小写变体，但生成提示统一使用小写。
- goal 只说明脚本当时的意图，不代表成功结果或最新用户要求。
- 简报不显示 `//`、不重复打印 `(declared)`；显示 `intent: <短正文>`，开头统一说明历史声明语义。
- 注释存在性的加分必须单独评估。如果所有脚本都有 goal，固定加分在这些脚本之间没有区分能力；导航正文与打分收益应分开统计。

### 4.2 blocked

- 本版允许解析为受限排序信号，但不进入 `[Outstanding Context]`，不显示 blocked 正文，不维护“仍未解决”的状态。
- 加分作用于声明所在的历史脚本，不因再次压缩而刷新时间；只在原事件仍处于近期区间时生效。
- 不新增强制写 blocked 的提示规则；先用合成场景和已有注释验证，避免制造注释负担。
- 若消融实验显示净退化，生产权重设为 0；这属于计划内的测量裁决，不需要另开一轮产品讨论。

### 4.3 不进入本版的声明

不新增 effects、verify、done、verified、next 声明族。尤其不能用 `verify` 屏蔽失败结果，也不能用 delete/rename token 生成缺乏路径和成功证据的文件事实。

## 5. 预算与呈现的最终原则

### 5.1 两层限制必须同时成立

用户、助手、工具活动各有分配额度；最终渲染的整个新简报还必须满足总字符上限。阅读提示、段标题、出处、换行、折叠标记和头部区段均计入实际成本。

取消固定的“最近 16 条用户消息”和新路径中的全局 80 块上限，不代表取消总预算。正常路径先缩短长文本，再折叠低价值工具活动；对极端大量的用户/助手条目，最后才折叠较旧连续片段。

“每条完整保留”仅对能装入预算的情形成立。不得将固定语料上的 100% 存续率写成任意输入的不变量。

### 5.2 省略信息必须可行动

文本省略说明包含原始显示文本总长度、实际省略量和 `#N`；工具省略按“脚本活动条数”计数，不把它叫作原文行数。范围只称搜索边界，不声称其中每个编号都属于省略集合。

字符口径统一写入执行计划：预算与偏移按 JavaScript UTF-16 单位记账，实际截取遵守字素边界。中文常用字一般为一个单位，组合字符可能占多个单位。不要把字符数当成精确 token 数。

### 5.3 时间线与状态

用户要求、助手判断、工具意图及观测结果按原始顺序输出。最新出现的要求也不自动等于当前已确认目标；原始请求若保留，应称为历史起点，而不是永久置顶的当前任务。

自动简报遵守有效编辑投影，read/scan 则访问已存原始证据，二者文字可能不同，阅读提示必须说明这一点。失效处理同时约束正文和旧头部：即使编辑后已没有有效 codemode 条目，也不能回退旧路径而重新合并被屏蔽的内容。

尾部原文承担继续任务的主要作用，但可能因显式 `keep:0` 或安全切点不足而不存在；不能在提示中保证“当前任务总在尾部”。简报不重复消耗预算展示已完整保留的尾部。

分段读取不得返回无法前进的空页：窗口小于一个完整字素时说明所需长度；单个病理字素超过读取硬上限时明确拒绝，作为本版可读完保证的技术例外，不声称原文已经丢失。

## 8. 本版不需要解决的事情

- 不建设当前任务状态机、永久阻塞表、意图账本或完整文件状态数据库。
- 不索引旧压缩摘要、custom store、图片像素和隐藏推理。
- 不改宿主日志格式、消息编号、分支树或持久化已有会话正文。
- 不为了实验新增公开配置、依赖或 CI 流水线。
- 不保证任意历史都可重放成外部世界的过去状态。
- 不以本机统计、六次冒烟或论文结果宣称新策略已普遍有效。
