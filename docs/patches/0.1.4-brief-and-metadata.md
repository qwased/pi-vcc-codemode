- 代码基线：0.1.3（`79ffc39`）。
- 依据：[0.1.4 审阅与修订计划](../plans/CODEMODE_0.1.4_REVIEWED_PLAN.md)（第二版）。
- 状态：**已实施**；确定性测试、真实会话全链路重放与包体检查均通过（见 §4）。

## 1. 修了什么

| 缺陷（审阅编号） | 现象 | 处理 |
|---|---|---|
| D1 / F4（P3） | 压缩条目的 `details.sections` 由整篇摘要的正则收集，正文里的 `[user]`、`[assistant]` 以及 brief 正文中的标题行都会被当成章节 | 新路径只从裁剪后的专用 header 取完整保留的章节名；旧路径由 `mergePrevious` 回传实际合并出的章节名；debug 与持久化共用同一数组 |
| F9（H7） | `sectionOf` 在整篇旧摘要上找标题，brief 正文里顶格的章节标题行会被当成章节合并 | 只在第一个 `---` 分隔块之前的 header 区查找；病态输入单独测试 `prev` 与 `fresh` 两种来源 |
| D3 / F2（P1） | 纯空白 assistant 文本成为候选，渲染出只有 `(#N)` 的孤立引用行；正文以换行开头时引用也落在空行上 | 候选层丢弃 trim 后为空的 assistant 文本；渲染层把引用附到第一个非空白行，保留原文缩进与换行；不重排 `#N`、不改评分公式 |
| F10（H9） | `stripKnownNotes` 未剥离 `LIMITED_HISTORY_NOTE`，有限历史摘要再次被旧路径读取时说明会进入摘要 | 剥离链增加 limited note 正则；新路径与“limited 后切旧路径”均有测试 |
| F7（P5） | `Ignored:` 只列参数、不说实际执行了哪条路径；`mode:"scan"` 的纠正提示含糊 | `Ignored: …; action: <最终动作>`（9 种标签，含 `none (invalid request)`）；`mode:"scan"` 改为提示 `use scan:true with query for a literal scan`；正常调用输出逐字不变 |
| F1 / D6（P1） | 目标行标签是 `intent:`，与 `// goal:` 标记、README 用语不一致 | 统一为 `* codemode goal: … (#N)`；`code:` 兜底与仅工具名形状不变；不采用无标签方案 |
## 2. 没改什么

- 预算公式（`clamp(15 × blocks, 1100, 2000) × charsPerToken`）、借额顺序、折叠规则、召回排序、`#N` 空间、`version: 2` 全部未动。
- `HISTORICAL_NOTE` 文本与 395 单元长度未动（H2 不采用）；`// blocked:` 仍不渲染；未新增设置项。
- 非 codemode 会话仍走旧路径：8 行/120 行约束、直接工具行与默认查询返回文本保持上游行为。

## 4. 验证

- `bun run typecheck` 通过；`bun test` **900 pass / 0 fail**。
- Pi 1.0.0 与 Pi 1.4.0 两个宿主各跑一遍（安装版本经核对），结果相同；随后恢复锁定宿主。
- 包体：`pi-vcc-codemode@0.1.4`，50 个文件，无 `*.bak`、`dist/`、`research/`、`tests/`、`docs/`。
- **真实会话全链路重放**：同一批 97 个本机会话（76 个普通、21 个 codemode），在 0.1.3 与 0.1.4 上用生产 `session_before_compact` hook 重放，输入（切点、`previousSummary`、`fileOps`、预算）一致，只记录聚合数：
  - 70 个普通会话摘要 **70/70 逐字节相同**；
  - 21 个 codemode 会话：**0** 超预算、**0** 引用无法解析、阅读说明恰好 1 条；`details.sections` 含正文标签的会话 **21 → 0**；孤立引用行 **16 会话 / 58 行 → 1 会话 / 1 行**。剩余 1 行是 120 列换行边界把行尾引用挤到下一行，0.1.3 在同一会话同一行同样存在，不属于本次引用附着缺陷；
  - 普通会话的 `details.sections` 同样从 70/70 含正文标签降为 0。
- **召回**：3 个真实 codemode 会话上，9 次 `read`（全部返回期望的 `#N [role]` 头）、3 次 `range`、无命中 `scan` 与查询，两版输出逐字节相同。
- 以上真实会话证据只保留匿名聚合数；原始会话、路径与正文留在 git-ignored 的本地目录，不进仓库。
