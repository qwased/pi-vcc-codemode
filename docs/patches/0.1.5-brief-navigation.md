## 1. 做了什么

| 项 | 现象/目标 | 处理 |
|---|---|---|
| P0 围栏配平 | 头/尾摘录把围栏切开后，省略标记、段头、`* codemode …` 行和末尾说明全被吞进代码块；legacy 行级上限会留下裸收尾行 | 新增 `src/core/fences.ts`（行解析、状态机、`closeUnclosedFences`、`dropOrphanClosers`）。`excerptText` 在 marker 前补收尾、marker 后补开口，整段保留与末尾各闭合一次；`attachRef` 不写 info string；`capBrief`/`capBriefToLineBudget` 丢弃孤立收尾行；`assembleBriefBody` 与 `compileWithEffectiveHistory` 加最终不变量兜底（追加量计入 `usedChars`/`reservedChars`）。legacy 无围栏输出逐字不变。 |
| H2 中性结果导航 | 已配对结果只对 error 显示引用，未标错结果没有导航 | `renderToolCandidate`：有配对结果 → `{result #N}`；有错 → `{error observed; result #N}`，无结果不加编号。short/normal 成本都含后缀，选择前测量。 |
| H3 直接工具有限通道 | 大量高分 codemode 会挤掉最近的直接验证调用 | `allocateToolRole`：错误通道 20%（策略不变）+ 最近 2 个非 codemode 直接调用共享 20%，未用额度回池；其余按 score/recency；剩余额度升级 normal；超额时先降 normal→short，再按 普通→直接→错误 分层删除（最低分先删、同分 order 升序），marker 计数/范围增量维护。 |
| H1 最近长文本深度 | 固定预算下两条最近长报告都停在 64 单元 | 最近 6 条非空 assistant 文本中的最近 2 条（≥256 单元）在初始化最小成本时就把下限提到最多 256；额外成本上限 `min(384, floor(quota/4))`，每轮 +64、最多 3 轮，每次调用按当次 quota 重算，再走原有折叠/升级/步进。 |
| H4 历史来源提示 | 旧 header 被当成当前状态/已验证 diff | `compileWithEffectiveHistory` 在 header 前加一行 `HEADER_CONTEXT_NOTE`（100 单元含换行），计入既有 20% header 份额；空 header 不加；legacy 不加；不进 `HEADER_NAMES`/`details.sections`。 |
| H5 预算落库 + 指标 | 摘要里的预算口径无法核对，指标只看初选 | `details.briefBudget`（`charsPerToken`/`historyBlockCount`/`maxChars`/`usedChars`/`reservedChars`）+ `BriefSelection.metrics`/`detail.metrics` + 可选 `detail.targets`；`counts` 键与语义未动；旧记录只报 unknown。 |

## 5. 冻结 golden 的差异清单怎么复核

1. `tests/fixtures/allocator-golden.json` 不动；SHA 由两个 golden 测试各自钉死。
2. `tests/fixtures/allocator-golden-0.1.5.json` 的每条记录都带 `baseline` 与 `next`；`reason` 里写明阶段（H3/H1）、变化 counts 键、`usedChars` 变化与通道/目标数字。
3. 新增/删除的引用在 `refs.added`/`refs.removed`；折叠代价在 `folds`；文本是否变化由 `textChanged` 与会话内 sha 对照。
4. 复核新增记录：`bun test tests/allocator-golden-0.1.5.test.ts` 的“登记集合 === 实际变动集合”会阻止任何未登记差异。

## 6. 未验证与残留（如实记录）

1. **`trimHeaderToBudget` 的围栏行为未改**（D5）：header 的每个内容行都由 `section()` 生成，带 `- ` 前缀，行首围栏不可达；来源提示是一句普通英文，不含围栏字符。
2. **legacy `truncateTokens`/`truncateTokensHeadTail` 未做围栏处理**（D5）：它们是词边界截断，不在 P0 清单；本轮只按 D2 修 `capBrief`/`capBriefToLineBudget` 的孤立收尾行。因此**源本身未闭合的 legacy 摘要仍保持 0.1.4 原样**（合成快照 `legacy-fence` 逐字相同），新路径才补收尾。
3. **direct/error 通道删除分支当前不可达**：marker（≤ ~80 字符）是唯一在选出后才计入的成本，两个通道各占 20%，实测 881 个预算点（277 / 497 次 normal 删除）中通道删除恒为 0。代码保留分层删除作为安全网，测试以“若删除发生则更低优先级层必须已空”的不变量断言，并在此明确它没有被真实触发过。
4. **没有 0.1.5 的真实会话 hook 全链路重放**：§4.6 是 compact-all 编译视图，输入（切点、previousSummary、fileOps、设置）与生产 hook 不同，不能当作 hook 等价重放；也没有 TUI/无界面人工验收与私有会话任务级实验。
5. **`#N:path:full` 的 50KB 字节截断**（`src/core/drill-down.ts`）仍不看围栏：它是 recall 输出而非摘要，缺陷报告已注明影响面小，未纳入本次。
6. **hash 记录的 refs 差异**依赖归档 0.1.4 构建重放出的基线文本；已核对 242/242 与 fixture 完全一致（kind/used/reserved/counts/text 或 sha），但重放使用的是当前 `tests/support/allocator-cases.ts`，与 fixture 的 `generatedFromCommit` 相同。
7. **预算矩阵不覆盖真实字符率**：cpt 取 2/4/6 三档（校准上下限与默认），不枚举 2 与 6 之间的所有小数；`briefBudget` 记录的是实际值，可在真实会话上用审计核对。
